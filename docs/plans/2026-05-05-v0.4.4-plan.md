## Context

v0.4.3 shipped 2026-05-04 (Classic Automation token, npm publish via `publish.yml`). Real-world usage in the user's downstream project at `D:/Projects/career ops` surfaced two correctness bugs after a same-day rotate→config-tweak→rotate sequence, plus an aligned regex sweep:

1. **Same-day archive clobber.** `scripts/collab-rotate-log.sh:142-154` writes the archive with `> "$ARCHIVE_FILE"` (clobber). Filename is `${AGENT}-${NOW_DATE}.md` — date-only, no timestamp. A second rotation on the same day overwrites the first archive verbatim. Marker-block summaries in the live log survive (one-line Receipt info), but full entry bodies are lost. Reproduces with: rotate → change `rotate_keep_recent` → rotate. The downstream project recovered only because a pre-flight backup zip happened to preserve evidence; otherwise 17 entries would have been lost permanently.

2. **Advisory treadmill.** `scripts/collab-check.sh:137-145` triggers the rotation advisory purely on `wc -l > threshold`. It does NOT check whether rotation would actually archive anything. When the live log has `≤ rotate_keep_recent` entries (already at minimum), rotation is a no-op but the line count remains over threshold → advisory persists → user runs rotate → "nothing to do" → loop. UX encourages the very re-rotation that triggers bug #1.

3. **Stats regex desync (G3, post-review promotion).** `scripts/collab-check.sh:44` (`--stats` mode) uses the legacy `^## 20[0-9]{2}-[0-9]{2}-[0-9]{2}T` regex — same bug v0.4.2 fixed in `collab-rotate-log.sh:84`, never propagated to `collab-check.sh`. `--stats` has been silently undercounting projects using date-only entry headers since v0.4.2. Bundling here keeps the regex unified across the file and the CHANGELOG honest.

Issues 3 and 4 from the field report were tagged "do not report" by the downstream Claude (content-shape question and config-preservation philosophy) — out of scope.

## Group-by-group detail

### G1 — Same-day archive append (no clobber)

**Bug.** `scripts/collab-rotate-log.sh:142-154` writes the archive with shell `>` redirection. The filename is date-stamped, so any second rotation on the same date silently destroys the prior archive's body content.

**Fix.** Change the write semantics to **append-on-existing-archive, fresh-write-on-new-day**. No `--force` flag, no opt-in clobber — same-day overwrite has no realistic use case (verified during plan review; if a user genuinely wants to start fresh, they can `rm .collab/archive/agents/<agent>-<date>.md` manually before re-running rotate).

**Why append (not timestamped filenames, not refuse-with-error):** the archive grows linearly per agent-day, stays one human-readable file per day, and the existing wildcard glob (`tests/test-collab-rotate-log.sh:53` uses `claude-*.md` already) keeps working. Refuse-with-error would force the user into either manual cleanup or `--force`, both worse UX than transparent append.

**Behavior matrix:**

| Archive file state | Behavior |
|---|---|
| Doesn't exist | Fresh-write (frontmatter + body header + archived_block) — current v0.4.3 behavior. |
| Exists, valid frontmatter | Append H3 continuation header + archived_block to file body. **Frontmatter NOT rewritten.** |
| Exists, no frontmatter (corrupt or hand-edited) | Append H3 continuation header + archived_block as-is, no frontmatter manipulation; emit stderr warning advising repair. |

**Implementation steps:**

1. **Detect existing archive.** Right before the write block (`scripts/collab-rotate-log.sh:142`), branch on `[[ -f "$ARCHIVE_FILE" ]]`.
2. **Fresh-write path** (file absent): unchanged from current v0.4.3 — emit frontmatter, body header, archived_block via `>` redirection. Print stderr `rotate: wrote <N> entries to fresh <ARCHIVE_FILE>`.
3. **Append path** (file exists):
   - Detect frontmatter via `awk 'NR==1 && /^---$/ { exit 0 } { exit 1 }'` (presence of `---` on line 1).
   - **With frontmatter:** append `\n\n### Continued — rotated <ISO-8601 time>\n\n${archived_block}\n` to file body via `>>` redirection.
   - **Without frontmatter:** same append, plus stderr warning `rotate: WARNING <ARCHIVE_FILE> has no frontmatter; appending raw. Consider repairing the archive file.`
   - Print stderr `rotate: appended <N> entries to existing <ARCHIVE_FILE>`.
4. **`last-updated` field NOT rewritten.** The H3 continuation header (`### Continued — rotated <ISO>`) carries the freshness timestamp. Rewriting the frontmatter field would require an awk in-place rewrite with cross-platform portability concerns (BSD vs GNU awk) for purely cosmetic gain. Drop.
5. **H3 (not H2) for the continuation header.** Critical: H2 (`##`) is the entry-header level. Tools or readers that count `^## ` lines (e.g., `grep -c '^## '` on the archive) would see continuation markers as entries. H3 (`###`) avoids this collision. The rotation regex at `scripts/collab-rotate-log.sh:84` (`^## 20[0-9]{2}-...`) wouldn't match the H3 line anyway, but using H3 also makes downstream tooling correct by construction.
6. **Final-line user message.** Current `:211` says `rotate: archived ${cut_idx} entries to $ARCHIVE_FILE; kept $KEEP recent entries in $LOG.` — change to `rotate: archived ${cut_idx} entries (appended to $ARCHIVE_FILE); kept $KEEP recent entries in $LOG.` on append, or `... (wrote $ARCHIVE_FILE); kept ...` on fresh-write. The substring `archived ${cut_idx}` is preserved in both variants — existing test assertions like `tests/test-collab-rotate-log.sh:104,179,194` (which match `archived 8`) stay green without modification.
7. **Idempotency invariant preserved.** Rotation logic only ever pulls from the live log (`tmp_norm`), never from the archive. The `entry_starts <= KEEP` short-circuit at `:87-90` still applies. The append change does NOT introduce duplicate-entry risk because rotation only fires when there are NEW entries beyond `KEEP` in the LIVE log.
8. **`collab-now.sh` for the timestamp.** Reuse `bash "$HERE/collab-now.sh"` (already used at `:148`). Output is `2026-04-22T10:15:30-05:00` — fine for a Markdown header line.

**Edge cases tested (NOT production code paths):**
- Existing archive ends without trailing newline → `printf '\n\n### Continued ...'` prepends two newlines; even a trailing-newline-less file becomes well-formed.
- Existing archive has frontmatter but no body header (`# <agent> — Archived entries`) → append still works; body is just appended after existing content.
- `--dry-run` with existing archive → existing dry-run short-circuit at `:135-140` is BEFORE the write block, so no fresh-write/append distinction needed in dry-run output. The dry-run message `rotate: would archive ${cut_idx} entries to $ARCHIVE_FILE` stays accurate (omits the append-vs-fresh distinction; cosmetic).

**Tests** (extend `tests/test-collab-rotate-log.sh`, in a new `# --- v0.4.4: same-day archive append ---` section to keep the file's existing version-grouping convention):

- **`rotate_twice_same_day_with_keep_change`**: initial rotate with `--keep 8` (12-entry log) → archive contains entries 1..4. Second rotate with `--keep 3` → archive contains entries 1..4 AND entries 5..9, separated by `### Continued — rotated <ISO>`. Live log keeps 10..12. **Critical assertion**: clobber bug fixed.
- **`rotate_appends_with_continued_marker`**: assert exactly one `### Continued — rotated ` line in archive after the second rotate.
- **`rotate_first_time_unchanged`**: fresh repo, first rotate → archive structure byte-identical to v0.4.3 output (no regression on fresh-write path).
- **`rotate_appends_to_archive_without_frontmatter`**: hand-craft an archive file with no frontmatter (just markdown body). Run second rotate. Assert content appended, stderr warning emitted (capture stderr via redirect).
- **`rotate_dry_run_with_existing_archive`**: existing archive present, `--dry-run` second rotate → would-archive message shown, archive byte-equivalent to before, live log byte-equivalent to before.

### G2 — Content-aware rotation advisory

**Bug.** `check_rotation_threshold` at `scripts/collab-check.sh:120-148` advises rotation whenever `wc -l > threshold`, regardless of whether rotation would actually do anything. When entry count is already at `rotate_keep_recent`, rotation is a no-op but the line count stays high (because each entry is itself long). User runs rotate → "nothing to do" → next check still says advisory. Three-action loop per check.

**Fix.** Make the advisory content-aware: count actual entries in the live log; compare to `rotate_keep_recent`; emit a different advisory when rotation would be a no-op.

**Implementation steps:**

1. **Read `rotate_keep_recent` from config** inside `check_rotation_threshold`, after the `rotate_at_lines` read at `:124-126`. Validate as positive numeric (regex `^[0-9]+$` AND value `> 0`); on any parse failure or non-positive value, fall back to default `3` (matching `scripts/collab-rotate-log.sh:62-64`'s fallback chain).
   ```bash
   local keep_recent
   keep_recent=$(awk -F': *' '/^rotate_keep_recent:/ { print $2; exit }' "$cfg" 2>/dev/null || true)
   [[ "$keep_recent" =~ ^[0-9]+$ ]] && [[ "$keep_recent" -gt 0 ]] || keep_recent=3
   ```
2. **Count entries with the v0.4.2-corrected regex.** Inside the per-log loop (`:129-146`), after the `count > threshold` check fires:
   ```bash
   local entry_count
   entry_count=$(grep -cE '^## 20[0-9]{2}-[0-9]{2}-[0-9]{2}([T ]|$)' "$log" 2>/dev/null || echo 0)
   ```
3. **Branch on `entry_count <= keep_recent`:**
   - **If true** (rotation would be a no-op): emit `advisory: $log is $count lines but already at rotate_keep_recent=$keep_recent ($entry_count entries). Rotation would be a no-op. Consider raising rotate_at_lines in .collab/config.yml, or accepting the verbose Receipt size.`
   - **If false** (rotation would archive entries): emit current advisory unchanged: `advisory: $log is $count lines (threshold $threshold). Run: ./scripts/collab-rotate-log.sh $agent`.
4. **Return code unchanged.** `check_rotation_threshold` is non-fatal (`|| true` at `:148`). Both advisory variants are non-fatal.

**Acknowledgment of repeat-firing concern (raised in plan review):** the alternative advisory will fire on every `collab-check` run as long as the log is over threshold AND at keep-minimum. This is intentional: it's a single decision the user makes (raise `rotate_at_lines`, trim entries, or accept). The pre-fix treadmill was a 3-action loop (advisory → run rotate → no-op stderr → next check still advises) that the user could feel pressured to resolve. The post-fix advisory is a 1-decision informational message; user can silence it by tuning config OR accept it as background noise. No suppression mechanism added — that's a v0.5.0 concern if it becomes a real complaint.

**Edge cases:**
- `rotate_keep_recent` not in config (legacy install) → default `3`.
- `rotate_keep_recent` is non-numeric, zero, or negative → default `3` (validated by step 1's regex + `-gt 0` check).
- Log has 0 entries (handoff blocks only or empty) → `entry_count=0 ≤ keep_recent`, alternative advisory fires. Correct: rotation is genuinely a no-op.

**Tests** (extend `tests/test-collab-check.sh`):

**Critical fixture note (raised in plan review):** the existing `tests/test-collab-check.sh:1-71` builds a hand-crafted minimal repo with no `agents.d/*.yml` descriptors and no `config.yml` — `check_rotation_threshold` would silently return 0 in this fixture. Advisory tests need a DIFFERENT fixture that runs `init_with_all_agents` first (see `tests/test-collab-rotate-log.sh:38-44, 134-145` for the canonical pattern). - **`advisory_when_over_threshold_and_entries_exceed_keep`**: log with 8 dated entries, `rotate_keep_recent=3`, line count > threshold → original "Run: ./scripts/collab-rotate-log.sh" advisory emitted (substring match).
- **`alternative_advisory_when_at_keep_minimum`**: log with 3 dated entries, `rotate_keep_recent=3`, line count > threshold → "rotate_keep_recent=3" + "Rotation would be a no-op" emitted; original "Run: ./scripts/collab-rotate-log.sh" NOT emitted (negative substring assertion).
- **`alternative_advisory_when_below_keep`**: log with 2 dated entries, `rotate_keep_recent=3`, line count > threshold → alternative advisory.
- **`no_advisory_when_under_threshold`**: log under threshold → no advisory line emitted (both branches silent).
- **`alternative_advisory_with_legacy_config`**: config without `rotate_keep_recent` line → default `3` used; with 3 entries over threshold → alternative advisory emitted.
- **`invalid_keep_recent_falls_back_to_default`**: config `rotate_keep_recent: -5` → treated as default `3`; with 3 entries over threshold → alternative advisory.
- **`regex_alignment_advisory_vs_rotate`**: assert that the regex literal in `scripts/collab-check.sh` (G2 advisory entry-count) matches the regex literal in `scripts/collab-rotate-log.sh:84`. Implement as `grep -F` lookup of the literal string `'^## 20[0-9]{2}-[0-9]{2}-[0-9]{2}([T ]|$)'` in BOTH files; both grep calls must succeed. Guards against silent regex desync in future edits.

### G3 — `--stats` regex alignment

**Bug.** `scripts/collab-check.sh:44` uses `'^## 20[0-9]{2}-[0-9]{2}-[0-9]{2}T'` — the legacy v0.4.1-and-earlier regex requiring a `T` suffix. v0.4.2 fixed the same bug in `collab-rotate-log.sh:84` to allow date-only headers (`## 2026-04-28 task title`). The fix never propagated to `collab-check.sh`. `--stats` has been silently undercounting entries for any project using date-only headers since v0.4.2.

**Fix.** One-line regex substitution at `scripts/collab-check.sh:44`:
```bash
# before:
entries=$(grep -cE '^## 20[0-9]{2}-[0-9]{2}-[0-9]{2}T' "$log" 2>/dev/null || true)
# after:
entries=$(grep -cE '^## 20[0-9]{2}-[0-9]{2}-[0-9]{2}([T ]|$)' "$log" 2>/dev/null || true)
```

This is now the THIRD location of this regex literal (rotate-log.sh:84, check.sh advisory in G2, check.sh stats in G3). The G2 `regex_alignment_advisory_vs_rotate` test catches advisory drift; add a parallel test for `--stats` alignment.

**User-visible behavior change.** Projects using date-only headers will now see correct (higher) entry counts in `--stats` output. CHANGELOG entry under "Fixed" makes this explicit.

**Tests** (extend `tests/test-collab-check.sh` --stats section if one exists; otherwise add to the new v0.4.4 section):
- **`stats_counts_date_only_entries`**: build a log with 2 date-only entries (`## 2026-04-28 task title`) + 1 datetime entry (`## 2026-04-29T10:00:00 task`) → `--stats` reports `entries: 3` (NOT 1, which is what pre-fix would emit).
- **`stats_regex_matches_rotate_regex`**: extend `regex_alignment_advisory_vs_rotate` (or add sibling test) — assert the same regex literal at `collab-check.sh:44` AND `collab-check.sh` (advisory site) AND `collab-rotate-log.sh:84`. Three-way agreement.

## Risks and mitigations

- **G1 append produces archives with mixed CRLF/LF if the existing archive was hand-edited on Windows.** Mitigation: rotation operates on the live log via CRLF normalization (`:67-70`), but the archive append targets whatever line ending the existing archive uses. With `printf '\n\n### Continued ...\n%s\n'`, the appended block uses `\n` regardless of the existing file's convention. **Decision**: live with it for v0.4.4 — rare, not data-loss; document under "known limitations" in the migration summary if it surfaces. A future patch could detect existing CRLF and match.
- **G1/G2/G3 regex literal lives in 3 places.** Mitigation: `regex_alignment_*` tests assert literal equality. If the regex needs another change (e.g., supporting BCE dates or T+timezone-only), the alignment tests force whoever changes it to update all three sites.
- **Migration sentinel writer must be the chain runner, not the migration body.** Mitigation: the v0.4.2 G8 mechanism handles this automatically. The new migration body just runs `mlog_action`, no sentinel-writing code.
- **Concurrent rotation race becomes worse under append.** Mitigation: out of scope for v0.4.4; documented in migration summary. Two clobbers produced one valid archive (the loser's content was destroyed but the survivor was clean); two appends can interleave bytes mid-write. Mitigation rationale: rotations are user-initiated and synchronous; concurrent rotation requires the user to invoke the script twice in parallel, which is not a real-world workflow.
- **G3 user-visible behavior change.** Projects with date-only headers will see higher `--stats` entry counts after upgrade. Mitigation: explicit CHANGELOG "Fixed" entry; this is the correct count, not a regression.
- **Plan-review note on advisory repeat-firing (G2).** The alternative advisory will keep firing on every `collab-check` run if the user ignores it. This is intentional and acceptable: it's an informational, non-fatal, single-decision message (not a 3-action loop). Suppression mechanism is a v0.5.0 concern if it becomes a real complaint.

- **Continuation marker as structural HTML comment** (`<!-- collab:archive-continuation -->`). Rejected for v0.4.4: H3 markdown header is sufficient and human-readable. Structural marker can be added in v0.5.0 if a future tool needs to parse continuations programmatically.
